# Verification record

**What this is.** Evidence that the nine defects raised by the external audit
were fixed, and that fixing them did not change any result the report depends
on. It records what was actually run and what came back, not what was intended.

**Scope.** The audit validated the science - the model, the reward, the
observation space, the experimental design - and none of those were touched.
Every change here is to correctness of tooling, reproducibility, or accuracy of
documentation.

**Dates.** Remediation 7-8 September 2026, against the tree tagged
`pre-remediation-audited`.

**The re-run evaluation reproduced the original numbers exactly.** All 150

### D1 — Route generation was not reproducible

`networks/generate_routes.py` seeded from `hash((scenario, seed))`. Python
salts string hashing per process, so the same command produced different
traffic on every run.

**The failure, reproduced before fixing** (three fresh interpreters, same
scenario and seed):

```
ns_heavy_seed100  vehicles=1759  sha256=87f7d8c223546767  first=E2C_0 …
ns_heavy_seed100  vehicles=1759  sha256=e273676aca655ef1  first=S2C_0 …
ns_heavy_seed100  vehicles=1867  sha256=f3234ad60916c642  first=W2C_0 …
```

Three different hours of traffic, and even a different vehicle count.

**After the fix** (`zlib.crc32` of `"<scenario>_<seed>"`), three fresh
interpreters:

```
ns_heavy_seed100  vehicles=1748  sha256=7d1314eeba87edaf  first=N2C_0 …
ns_heavy_seed100  vehicles=1748  sha256=7d1314eeba87edaf  first=N2C_0 …
ns_heavy_seed100  vehicles=1748  sha256=7d1314eeba87edaf  first=N2C_0 …
```

A different scenario at the same seed number still yields different traffic
(`balanced_seed100` → 1620 vehicles), so the scenario name is still mixed in.

**An honest limitation, stated plainly.** The committed route files were
generated by the *old*, salted code. They therefore cannot be regenerated by
the fixed generator — note that 1748 above is not the committed file's 1783.
The committed files remain authoritative for every published number, which is
why the generator now refuses to overwrite them:

```
$ python networks/generate_routes.py
Refusing to overwrite 40 existing route file(s) in …/networks/routes.
…
$ echo $?
1
$ git status --short networks/routes | wc -l
0
```

Regenerating requires an explicit `--force` and, to stay honest, retraining and
re-evaluating. Guarded by `tests/test_route_determinism.py`, which pins the
seed to its literal CRC value so a return to any process-dependent function
fails immediately.

### D4 — The report claimed a provenance guarantee it did not have

Confirmed false before fixing: none of the eight table blocks written by
`make_tables.py --write` appeared anywhere in `REPORT.md`.

Fixed by the preferred route. Four tables now sit between paired
`BEGIN GENERATED` / `END GENERATED` comments and are spliced in by
`make_tables.py --write`. The splice is idempotent (same md5 on a second run)
and fails loudly on a missing or unpaired marker rather than writing a
half-updated report. `tests/test_report_matches_data.py` closes the loop by
parsing the numbers back out of the committed markdown and checking them
against the CSVs, so the §8 claim is now enforced rather than asserted.

The §8 wording was also corrected: it previously said *every* number is
generated, which overstated the mechanism, since figures quoted in the prose
are still read off the tables by hand.

### D5 — `MIN_GREEN` defined twice

`baseline/fixed_time.py` now imports it from `eval/simulation.py` alongside
`YELLOW_TIME`. `test_min_green_is_not_defined_twice` asserts the two names are
the same object, so a re-introduced copy fails the suite.

### D6 — The honesty metric failed silently to zero

`run_episode` read the insertion backlog inside a bare
`contextlib.suppress(Exception)`, so a failed measurement produced `0` — the
same value that means "no demand was dropped", which is exactly the reading
§5.2 of the report relies on.

Now catches `traci.TraCIException` only, prints a warning naming the episode,
and records the sentinel `-1`. `eval/evaluate.py` surfaces any `-1` as an
explicit warning before the honesty summary, and
`test_the_insertion_sentinel_survives_a_round_trip` checks it is not flattened
to 0 by the CSV round-trip.

The metric was also relabelled throughout, since it is a snapshot of the
backlog at t=3600 rather than a per-hour count. See §4 for the resulting
wording change in the report.

### D7 / D8 — Documentation and constants

`train_dqn.py` now states ~46 min (logged: 45.9) and `train_ppo.py` ~26 min
(logged: 26.0); they had each other's figures. `agent/training.py` imports
`N_INCOMING_LANES` instead of hard-coding `8.0` — it is the constant the reward
divides by, so a literal there would silently mislabel every training curve.

### D9 — Packaging and hygiene

Added `pyproject.toml` (Python floor, pytest and ruff configuration).
`_quiet_stdout` renamed to `quiet_stdout`, since it is used across a package
boundary. `EpisodeLogger.algo`, previously assigned and never read, now labels
the progress lines.

**One item downgraded, with justification.** The audit flagged `pandas` as an
unused pin. It is unused by *this project's* code, but it is a hard runtime
requirement of both `sumo-rl` and `stable-baselines3`:

```
sumo-rl            -> ['pandas']
stable-baselines3  -> ['pandas']
```

Dropping the pin would not remove the dependency, only unpin it — trading
reproducibility for nothing. It is kept, moved to a clearly labelled
"pinned transitive dependencies" section explaining why.

**One item deliberately not fixed.** `run_episode` still builds a throwaway
controller via `controller_factory(None)` to read the `uses_env_control` class
attribute. Removing it means changing the factory contract across four call
sites for a cosmetic gain, on the one code path every published number flows
through. The instantiation is free (no controller does work in `__init__`) and
is explained by a comment. Not worth the risk during a remediation pass.

## 4. Numbers that changed, and why

Three changes to `REPORT.md`. **No measured value changed** — every difference
below is a rounding correction, a relabel, or added rows.

**1. `ns_heavy` in the greedy-vs-DQN table: "8% better" → "7% better."**
Greedy 22.29 s, DQN 20.64 s. Expressed relative to the worse controller, as
every other row in that table is, the gap is 7.4% → 7%. The hand-written 8% was
inconsistently rounded. This is precisely the drift D4 predicted, and it was
found by generating the table rather than by reading it.

**2. The insertion-backlog table gained three rows and a new column label.**
Previously it listed only the four largest values; the generator emits every
non-zero mean, which adds `ns_heavy`/fixed-time (5) and `ew_heavy`/fixed-time
(4), and names the controllers in full. The header changed from
"Vehicles not inserted (mean per hour)" to "Still awaiting insertion at the
hour's end (mean)", per D6. The two figures the report's argument rests on are
unchanged: 227 on `surge`, 95 on `peak`.

**3. §5.2 and the appendix wording.** §5.2 now states that the figure is a
snapshot at t=3600 rather than a running count, and the appendix entry records
the `-1` sentinel. The argument is untouched: the untuned plan still fails to
admit ~10% of `surge` demand, and its reported waiting time is still an
underestimate of its true cost.

One further difference, in the data rather than the report: in
`evaluation_summary.csv` the `vehicles_not_inserted_max` column now prints `0`
where it printed `0.0`, in 24 rows. This is the append-mode type artefact the
audit noticed (PPO's rows differed from the rest) resolving itself now that
every row comes from one fresh sweep. Zero numeric values differ.
